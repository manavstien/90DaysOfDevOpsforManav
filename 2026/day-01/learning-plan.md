My 90-Day DevOps Learning Plan
Where I am today
I am a working software engineer with experience in Java-based applications, web development, application servers, Gradle builds, and enterprise integrations. I understand how applications are developed and run, but I am at the beginning of building structured, hands-on DevOps and cloud engineering skills.
What DevOps and Cloud Engineering mean to me
DevOps is the practice of bringing development and operations together through automation, collaboration, reliable delivery, and continuous improvement. Cloud engineering is designing, deploying, operating, and securing applications and infrastructure using cloud platforms. Together, they help teams ship software faster without sacrificing reliability or security.
Why I am starting
I want to take ownership of the complete software lifecycle—not just writing application code, but also building, deploying, monitoring, and improving it. DevOps and cloud skills will help me become a stronger, more independent engineer and prepare me for roles with greater technical responsibility.
My 3 goals for the next 90 days
1. Build strong foundations: Become comfortable with Linux, networking basics, Git, shell scripting, and troubleshooting common deployment issues.
2. Automate software delivery: Build a working CI/CD pipeline that checks out, builds, tests, and packages a Java application, then deploys it to a test environment.
3. Deploy and operate an application: Containerize an application with Docker and deploy it to a cloud-based Kubernetes environment or a local Kubernetes cluster first; add basic logs, health checks, and monitoring.
My 3 core skills
- Linux and networking: command line, permissions, processes, services, logs, SSH, ports, DNS, and troubleshooting.
- CI/CD and automation: Git, scripting, build tools, pipeline design, automated tests, and deployment workflows.
- Containers and cloud infrastructure: Docker, Kubernetes fundamentals, cloud compute/networking/IAM concepts, and basic monitoring.
My weekly commitment
- Weekdays: 2 hours per day, 5 days a week.
- Weekends: 4 hours per day, split between hands-on practice, revision, and documenting what I learned.
- Weekly total: Approximately 18 hours. If work gets busy, I will protect a minimum of 30 minutes of focused learning rather than skip the day completely.
My consistency rules
1. Learn by doing: spend more time in the terminal and building than watching videos.
2. Keep a daily record of what I learned, what I built, and what blocked me.
3. Push exercises and project progress to GitHub regularly.
4. Review progress every Sunday and adjust the next week's tasks without abandoning the 90-day goals.
5. When stuck, investigate systematically, document the fix, and ask for help with the exact error and steps tried.
My commitment: For the next 90 days, I will show up consistently, build practical projects, and measure progress by what I can explain and demonstrate—not by how many videos I complete.
